# Contributing

Corrections and real-world traps are the most valuable contributions here.

## What is especially welcome

| Contribution | Notes |
|--------------|-------|
| Technical corrections | API details, wrong method names, advice that no longer holds |
| Traps found on real projects | The specific failure and how you noticed it |
| Measured numbers | Worth far more than estimates. See below. |
| A new mechanic preset | With pipeline, budget, traps, and what it demonstrates |

## Measured numbers

Most figures in `references/budget.md` are explicitly labelled starting points,
because they are not measurements.

If you measured something, that is a real upgrade to this skill. Include:

- The device, by name and year
- The browser and version
- What you measured, and how
- The number

Measured figures replace estimates and get labelled as measured.

## House rules

These are enforced, and a pull request that breaks them will be asked to change:

- `SKILL.md` and everything in `references/` is written in English
- `README.md` is bilingual, Portuguese first
- No emoji in `SKILL.md` or in `references/`
- No em dash character in any file
- Prefer tables and lists over long paragraphs
- Direct and technical tone, no filler
- Every number, limit, or budget is marked as an adjustable starting point unless
  there is a cited source

## Never invent a benchmark

The single rule that matters most. If a figure was not measured, it is an
estimate and must say so. A skill that states confident numbers it cannot support
teaches agents to do the same.

## Pull requests

Keep them focused. One correction or one addition per pull request is easier to
review and easier to revert.
